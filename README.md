# GithubCopilot_cheatSheet

## エージェント機能の使い方

GitHub Copilot のエージェント機能を使うと、単なるコード補完だけでなく、**調査・修正案の提示・複数ステップの作業支援**まで対話形式で進められます。

### できること

- バグの原因調査
- 関連ファイルの探索
- 実装方針の提案
- コードの修正案作成
- テスト追加やリファクタリングの支援
- Pull Request の要約やレビュー補助

### 基本的な使い方

1. **やりたいことを具体的に伝える**  
   例:
   - 「このエラーの原因を調べて」
   - 「このリポジトリで認証処理がどこにあるか探して」
   - 「この関数をリファクタリングして」
   - 「このPRの変更点を要約して」

2. **必要な情報を一緒に渡す**  
   精度を上げるために、以下を添えると効果的です。
   - エラーメッセージ
   - 対象ファイルや関数名
   - GitHub URL
   - 期待する動作
   - 修正方針や制約条件

3. **提案内容を確認しながら進める**  
   1回で完成を目指すより、次のように対話しながら詰めるのがおすすめです。
   - 「その理由を詳しく」
   - 「変更範囲を最小にして」
   - 「テストも追加して」
   - 「日本語コメント付きで」

### よくある依頼例

- **調査系**  
  「この例外の発生箇所を特定して」

- **実装系**  
  「README にセットアップ手順を追加して」

- **レビュー系**  
  「このPRの要点と懸念点をまとめて」

- **改善系**  
  「この処理をもっと読みやすくして」

### うまく使うコツ

- 依頼はできるだけ具体的にする
- 対象のリポジトリ・ブランチ・ファイルを明示する
- 「何を変えたくないか」も伝える
- 一度に大きく頼みすぎず、段階的に依頼する
- 出力結果はそのまま使わず、必ず確認する

### 依頼テンプレート

```markdown
目的: 何をしたいか
対象: リポジトリ / ファイル / PR / Issue
現状: 困っていること・エラー内容
期待結果: どうなってほしいか
制約: 変更したくない部分、使用技術、コーディング規約
```

### 注意点

- 自動生成されたコードや説明は必ずレビューする
- 権限が必要な操作は、環境や設定によって実行できない場合がある
- 曖昧な依頼だと、意図と異なる提案になることがある

### まとめ

エージェント機能は、**「質問して終わり」ではなく、開発作業を一緒に進めるための支援機能**です。  
具体的な依頼と十分な文脈を渡すことで、より実用的な提案を得られます。
